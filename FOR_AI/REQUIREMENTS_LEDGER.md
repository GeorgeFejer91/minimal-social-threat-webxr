# Requirements ledger

This ledger consolidates the user’s requests in chronological order. “Implemented” describes software state, not scientific validation.

| ID | Demand | Status | Notes |
| --- | --- | --- | --- |
| R01 | Investigate scientifically validated minimal 2D emotion/avatar stimuli | Researched | Candidate literature and libraries are in the bibliography; the project-authored faces are not validated. |
| R02 | Represent social agents with minimal game-like features that still carry social cues | Implemented prototype | Procedural 2D and 3D agents carry expression, orientation, role, gait, gesture, and dialogue cues. |
| R03 | Surround the observer with a group; introduce an approaching threat | Superseded in spatial layout | The approach remains; R20 replaces the surrounding ring with a front-facing crowd. |
| R04 | Agents become avoidant and afraid as the threat comes nearer | Implemented | Detection, alert, startle, fear, flee, and freeze are explicit agent fields. |
| R05 | Optional VR/MR, predefined background, or passthrough | Implemented where browser supports it | `immersive-vr` and `immersive-ar`; virtual clearing or transparent compositor background. Physical-device verification remains required. |
| R06 | Browser top-down companion synchronized in realtime | Implemented | Full scene snapshots and bounded commands. |
| R07 | Reuse the Affect Tracker’s VDO.Ninja solution | Implemented adaptation | VDO.Ninja SDK 1.5.5, data-only room/channel, no media tracks; a trial-start action starts broadcast and the companion auto-discovers. |
| R08 | Publish through GitHub Pages and provide a launch URL | Existing deployment; update pending | Repository remote and live URL are recorded in the README. New changes must be pushed/deployed after validation. |
| R09 | Smartphone-compatible layout like the Affect Tracker | Implemented | Safe areas, touch targets, scroll-safe canvases, and a single-column mobile layout. |
| R10 | Complete 2D phone trial; VR only optional | Implemented | 2D Canvas is the primary trial. WebGL/WebXR loads lazily. |
| R11 | Investigate publicly available human assets | Researched, not bundled | Rocketbox is the leading behavior-ready candidate; VALID is the leading demographic-identity candidate. |
| R12 | Agents meander asymmetrically, face/look at one another, converse, and organize socially | Implemented prototype | Six dyads, seeded independent trajectories, gaze targets, alternating talk/listen roles, and social links. |
| R13 | Generate sounds and short dialogue cues in a binaural manner | Implemented prototype | Caption semantics plus project-authored non-lexical synthesis; one HRTF-positioned source per active agent cue. Fixed recorded speech is recommended for a final study. |
| R14 | Group behavior changes when the threatening cue menaces toward the observer | Implemented | Individual detection delays create non-simultaneous alarm transmission and flight. |
| R15 | Add a first-read “for AI” folder with project scope, goals, bibliography, and source assets | Implemented | Root `AGENTS.md` mandates this folder’s reading order. |
| R16 | Make the threat a stylized shrouded darkness with faint agentic cues such as red eyes | Implemented | Generic project-authored shadow; not a film-character replica. |
| R17 | Use a scientifically grounded threatening sound range and binaurally bind it to the approaching agent | Implemented with caveat | 47/83 Hz amplitude modulation is used within the roughness regime motivated by Arnal et al.; the looming HRTF approach is informed by Taffou et al. and auditory-looming research. It is not a universal threatening pitch or a validated copy of a published stimulus. |
| R18 | Implement a working VR threat-approach scenario for social-neuroscience use | Working prototype | Automated software gates can pass; study readiness still requires acoustic calibration, headset tests, ethics/safety review, and pilot validation. |
| R19 | Remove the visible VR safety-limit marker and black warning sign; start the VR experiment with the right-controller A button | Implemented, later launch behavior superseded by R21 | The invisible 1.8 m constraint remains enforced. Right-hand `xr-standard` button index 4 restarts after completion or resumes a pause; R21 additionally makes the immersive launch click start/continue immediately. Either trigger remains pause-only. |
| R20 | Let dyads exchange friendly-valence tones; place a large crowd in front; keep the distant shadow initially invisible and increase its opacity during approach | Implemented prototype | Twelve agents form six front-facing dyads. Baseline cues use smooth, moderate-pitch, harmonic/consonant synthesis informed by affect research, with explicit cultural/validation caveats. The shadow starts at −16 m with zero participant-visible opacity and fades in monotonically with proximity. |
| R21 | Remove the readiness checkbox; expose direct Start 2D and Start immersive 3D controls; allow a running 2D trial to continue in XR | Implemented | The lazy 3D engine prewarms invisibly. The immersive button calls `requestSession` directly from its click and then starts/resumes the same trial clock. Right-controller A restarts/resumes and triggers pause. |
| R22 | Make synchronization easy from an external browser over VDO.Ninja | Implemented prototype | Starting either participant view starts the data broadcast without awaiting it before WebXR entry. The companion starts discovery when opened, retains retry/disconnect/source selection, and the host offers an external-browser companion link. |
| R23 | Add a dropdown-selectable publicly available human avatar | Implemented with caveat | The optional human crowd uses the bundled Cesium Man GLB (CC BY 4.0) in 3D and a human-proportioned project-authored 2D rendering. This asset is a format sample, not an emotion-validated social stimulus. |
| R24 | Add a spider as the third threat and make presence/audio more menacing | Implemented evidence-informed prototype | The bundled CC0 Huntsman Spider GLB has a procedural loading fallback. Both shadow and spider fade in during approach. Threat audio combines HRTF looming, inharmonic carriers, 47/83 Hz rough modulation, deterministic accelerating low pulses, noise, and spider-only clicks behind master gain/compression. The composite is unvalidated. |
